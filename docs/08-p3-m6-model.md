## 1. 这一期做了什么

需求 M6 的第二层：**把相关设定卡 + 章节正文喂给模型，输出结构化 issue 列表**（`severity` / 章节位置 / 冲突依据 / 建议）。确定性层能查的是「事实」——id 存不存在、章号重不重、伏笔回收了没有；这层要查的是**意义**：角色用了卡里明令禁止的能力、着过火的地方下一章还在、已经死的人开口说话。

### 1.2 一次模型检查读什么（prompt 里的东西 = 可展开的输入清单）

| 输入 | 为什么 |
|---|---|
| `novel.yaml`（渲染成一行） | 书名/体裁，模型的语气与定位 |
| `settings/world.md` | **硬约束**在这一节，M6 要查的「不可违背」都在这 |
| `outline/volumes/vNN.md` | 本卷目标：这一段该发生什么 |
| 本章登记的卡（`pov`/`characters`/`locations`；上限 6 张已在 2026-09-15 取消，见 `00` v0.37） | 事实的另一边 |
| 上一章的摘要与结尾 | 衔接类的矛盾只有看到它才可能被发现 |
| 本章 frontmatter（要点/摘要/登记的卡） | 章纲与实际写成什么的对齐 |
| 本章正文 | 被检查的对象 |
| `.novel（规则检查结果）` | **确定性层已经报过的**，明确要模型别重复 |

不含：全书主线、其它章节正文、文风样本。理由写在 §2.2。

### 1.3 输出契约（prompt 原文）

```
- 只输出一个 JSON 数组，不要解释、不要代码块围栏、不要 Markdown。
- 每个元素形如：
  {"severity":"error","where":"第 3 段｜陈默第一次开口","quote":"正文里的原句",
   "basis":"settings/characters/chen-mo.md 的「## 能力」写着……","suggestion":"改成……"}
- quote 必须逐字复制【本章正文】里的原句；找不到原句的问题不要报。
- basis 必须写出冲突的另一边：哪张卡的哪个字段、世界观哪条硬约束、或哪一章的什么事实。
- severity：error = 与已确立的事实直接冲突；warn = 可疑或前后不一致；info = 值得确认。
- 没有矛盾就输出 []，不要为了凑数报问题；不要报错别字、标点与文风问题（那不属于一致性）。
```

**为什么敢要求「逐字引用」**：`quote` 是作者核对这句话的唯一锚点，也是「点击跳转」将来能定位到正文位置的前提。要求模型逐字复制，比要求它描述位置靠谱得多。

### 1.4 解析：宽容在格式上，严格在可核对性上

`plan.ts` 的宽容（围栏、闲聊、字段别名）在这里照旧：`location`/`text`/`reason`/`fix` 都能吃，严重度接受 `高/中/低`、`严重/警告/提示`、`high/medium/low`，按严重度排序。

但有一条更严：**没有 `quote` 也没有 `basis` 的条目直接丢掉**，并给出一句「JSON 里有 N 条，但没有一条带 quote 或 basis（无法核对的结论不展示）」。需求 §8 把「误报 → 信任度下降」列为风险，一条作者无法核对的结论正是那种误报；宁可少报。`[]` 是**正常结果**（模型读完了，没看出矛盾），不是错误。

### 1.5 「先确定性后模型」真的落地了

这句话在需求里是分期顺序，在这里变成了 prompt 里的一段：确认性层的报告里属于本章的问题，以「【规则已经报过的（不要重复）】」列给模型，并在「这次喂了什么」里如实标出这个来源（`.novel（规则检查结果）`）。**两层的分工因此是可验证的**：同一个问题不该在报告里出现两次。规则报告由面板持有（第七期把它上提到 Panel 的收益在这里兑现），任务装配时一并交给 prompt 构建。

## 2. 三个需要记录的决定

### 2.1 模型检查不改任何文件，报告靠 `.novel/runs/` 留痕

第四种落盘策略 `report`：没有「采纳」这个动作，因为**报告本身就是产物**。任务跑完照旧写 `.novel/runs/<时间戳>-chapter-check.json`（输入清单、prompt、原始输出），与其它任务同一套留痕——这是需求 §5 的承诺，模型层的结论因此可回看、可对比。

### 2.2 范围是一章，且刻意不看全书

- **只喂一章正文 + 它登记的卡**。百万字塞不进 prompt；而「喂相关片段」会让检查的**射程**变得不可知——作者无法判断这次检查到底看过什么，也就无法信任它的沉默。
- **不喂其它章节正文**，只给上一章的摘要与结尾。跨十章的矛盾这一层查不出来，这是明确的能力边界，面板上也写着「只看到这一章与本章相关的几张卡」。
- **不报错别字、标点与文风**：那属于 P4。把它们混进一致性报告，会把真正的矛盾埋掉。

### 2.3 失败的一轮必须报失败（我跑模型时撞出来的真 bug）

我在隔离实例上真跑了一次这个任务，结果是：

```
reason=error  error=undefined   text=（空）
```

而面板显示的是「模型检查：0 条」加一个空的「原始输出」——**看起来像「模型读完了，没有问题」**，实际是模型那一轮根本没跑起来。原因是 `runner.ts` 只把「host 给了失败文本」当失败，而会话用 `reason: 'error'` 结束、不给文本时，它被当成正常结束。

后果不止于模型检查：任何正文任务在模型调用失败时都会给出**一个空预览**，作者完全可能「采纳」一个空结果。修法是把 `error` 这个终止原因认成失败，并说明「这一轮没有留下任何输出」。这条修复有 4 项断言（含「host 有原话时用 host 的原话」），用 stub 掉的传输层驱动 `startRun` 验的。

**这也是这一期最值钱的一条**：模型层的代码没写错，但模型层让我第一次真的走到了「一轮失败」这条路上。

### 2.4 模型结论暂时不做「忽略」（对需求的第二处偏差）

需求 M6 的交互写「可忽略某条」。确定性层做到了（key 是 `规则:文件:目标`，描述事实，重跑不变）。**模型层没做**，理由是模型输出不可复现：忽略键只能由内容派生（比如 `模型:章节:原文片段`），模型换个说法重报同一个问题时，那条忽略就会失效——一个**看起来记住了、其实没记住**的忽略，比没有更坏。

可选的中间路线（记下来备选，不是现在做）：允许「这一次报告里折叠这条」，只在面板内存里生效，下次运行清空——它能解决「读完这一段再往下读」，且不假装记住任何东西。

### 3.1 解析器与任务装配的断言

- 解析器：围栏与闲聊剥掉、字段别名、中文严重度映射、按严重度排序、只有 `quote` 的留下、**没有 quote 也没有 basis 的丢掉并给出原因**、同一句话去重（含尾随空格）、`[]` 是正常结果、非 JSON 给一句话而不抛异常。
- 任务装配：读到世界观硬约束、本章卡正文与本章正文、要求逐字引用与依据、明确不报文风、把规则已报的问题列进去、`kind/apply` 是 `issues/report`、输入清单如实（含 `.novel（规则检查结果）`）、**没有打开的章时明确拒绝**。
- runner：`error` 认成失败且说明没有输出、正常结束仍是 `onSettle` 且增量按累积长度投递、host 有失败文本时用原话。

### 3.2 渲染检查现在能执行「有结论」这条分支

`IssueList.tsx` 单独成组件并导出到 `__views`，因此渲染检查喂它两条真结论，断言**句子、依据、建议、严重度计数**都画出来了——不是只画一个空状态。这是 P2 那条教训（渲染通过 ≠ 分支被执行）在本期的又一次应用。

### 3.3 真实模型那一轮：我跑不通，以及为什么

按 `06`/`07` 的同一套办法起了隔离实例（`--profile novel --port 3099`），把 prompt 用**真的任务装配**生成（986 字符），POST 到 `/api/novel/task`，轮询到结束：

```
prompt chars: 986
inputs: novel.yaml, settings/world.md, settings/characters/chen-mo.md,
        settings/locations/qingshi-town.md, chapters/v01/c0001.md
--- run ---
reason=error  error=undefined  text=（空）
```

子会话的日志（`.dsh-home/sessions/_no-cwd/novel-c9a87794…/session.v3.jsonl.zstd`）**只有一行 header**：会话建起来了，但这一轮没有落任何内容；`turn/end` 的原因是 `error`。我的隔离 home 里没有可用的模型路由/凭据（`DEEPSEEK_API_KEY` 在我的 shell 里也不存在），所以**模型那一轮我这边跑不起来**——这与 P2 的 GUI 项同一性质：我的沙箱够不到的东西，只能交给作者。

这一跑的价值不是「验证通过」，而是它把 §2.3 那个真 bug 撞了出来。
