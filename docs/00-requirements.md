## 0. 结论摘要

做一个 **DSH Web 插件**（host 侧工具/服务 + GUI 侧栏面板），把 DSH 变成中文长篇网文的写作台。
小说工程以 **工作区 Markdown + frontmatter** 存放，一章一文件，人可读、可 Git、模型可直接读写。
AI 能力以 **面板按钮触发**，每次触发是一个「显式任务」：装配哪些材料、喂什么提示词、产出落到哪里，全部写在任务定义里，可查看、可重跑、可回滚。
模型 **复用当前 DSH 会话的供应商与模型**，不引入第二套 API Key。

## 2. 定位与非目标

### 2.1 一句话定位
**一个把「设定 → 大纲 → 正文 → 校验」串成闭环的长篇写作台**，AI 是每个环节的可调用工序，作者始终是最终决策者。

### 2.2 v1 明确不做
- 多用户协作、云端账号、在线同步
- 出版级排版与 PDF/EPUB 精细导出（v1 只做 md / txt 导出）
- 封面插画、插图、TTS（后续可另接生成类能力）
- 自动发布到任何平台
- **隐式上下文注入**：不偷偷把设定塞进你的普通对话。所有喂给模型的材料都来自显式任务定义
- 全自动「一键写完一本」（AI 只做工序，不做整书决策）

## 3. 数据格式

> **真源已移出本文**：完整目录树、各文件 frontmatter 规范、身份与引用规则、派生数据与扩展规则，见 [`03-project-structure.md`](03-project-structure.md)。
> 本文只保留不变量；两者冲突时以 `03` 为准。

### 3.1 不变量

- **正文与元数据分离**：frontmatter 是机器事实，正文是作者领地；编辑器只编辑正文那一段。
- **id 稳定不变**：章节身份来自文件名（`chapters/v01/c0001.md` → `c0001`），显示编号在 frontmatter 的 `number`。在中间插章时只分配新 id，不重编号任何人。
- **引用单向**：一律引用 id 字符串，反向查询由索引负责；不允许同一事实存两处。
- **纯文本**：v1 全部是 Markdown + YAML frontmatter，不引入数据库；索引是宿主进程内存里可重建的缓存，**不落盘**（P5 起，见 `03` §5）。
- **`summary` 是检索的第一层索引**，比全文省 token；由任务生成，可手改。

### 3.2 已定分叉（详见 `03` 第 2 节）

| # | 议题 | 决定 |
|---|---|---|
| S1 | 章纲位置 | 写进章节 frontmatter 的 `beats`；卷纲只写卷目标 |
| S2 | 设定卡组织 | 按类型分目录 `settings/<type>/<id>.md` |
| S3 | 伏笔与时间线 | 伏笔一物一文件（`settings/threads/`）；时间线单文件 |
| S4 | id 风格 | 英文/拼音 slug |
| S5 | 卷层 | 始终保留 `chapters/v01/` |
| S6 | `.novel/` 与 git | 索引不落盘（进程内存）；`runs/` 进 |

## 4. 功能模块

对应你勾选的 6 项 + 手动编辑，逐个定义「能力 / 交互 / 落盘 / 依赖」。

### M0 手动编辑（基础，其他模块的地基）
- 能力：章节树浏览、正文纯文本编辑、frontmatter 表单化编辑（下拉选角色/地点）、字数实时统计、保存即更新索引
- 落盘：直接写 `chapters/**/*.md`
- 依赖：无

### M1 设定库
- 能力：世界观/角色/地点/物品/势力的增删改查；别名维护；设定卡之间双向链接（某某出现在哪些章）
- 交互：设定卡列表 + 卡片编辑；从正文选中文本「建卡」
- 落盘：`settings/**`
- 依赖：M0

### M2 大纲与章节规划
- 能力：全书主线、卷纲、章纲（章名/目标/字数/节拍/出场人物）；AI 基于现有设定生成或续写卷纲、章纲；目标字数与实际的偏差视图
- 交互：卷章树 + 大纲编辑区；「续写卷纲」「按主线拆章」
- 落盘：`outline/**`；章纲与章节文件通过 id 关联
- 依赖：M1

### M3 正文写作
- 能力：
  - 按章纲生成整章
  - 续写（从光标处往下写）
  - 扩写（选中段落变长）
  - 改写（换写法/换节奏/换语气）
  - 重写（整章重来，保留大纲约束）
- 前情装配（2026-09-16 补，作者要求「续写、扩写时需要至少将上一章加入 prompt」）：五个正文任务（整章 / 续写 / 改写 / 扩写 / 润色）都带**上一章全文 + 摘要**，以及作者手挂的**参考章节**全文（章节 frontmatter 的 `contextChapters`，`03` §4.2）；**一致性检查（模型）仍只读上一章的摘要与结尾 800 字**（`08` §2.2 的能力边界不变），去 AI 味检查不带章节正文。
- 交互：编辑器内右键/工具栏按钮；**产出先预览 diff，确认后落盘**；流式输出
- 落盘：章节正文；每次任务写入 `.novel/runs/`
- 依赖：M0、M1、M2

### M4 文风统一与润色
- 能力：文风规则（`style-guide.md`）+ 风格样本随生成任务一起装配；「润色本章」「去 AI 味检查」（AI 口头禅、排比堆砌、总结句收尾、形容词密度、对话腔调）
- 交互：任务按钮 + 问题清单（可点击定位到正文位置）
- 落盘：润色结果同样走预览确认
- 依赖：M3

### M5 前文检索问答
- 能力：「某人上次出场在哪」「某物品第一次出现是哪章」「某设定在哪解释过」；返回章节定位 + 原文片段
- 方案：v1 用**结构化反查（frontmatter 的 characters/locations/items）+ 摘要索引 + 关键词检索**，不引入向量库；别名自动展开
- 交互：面板搜索框 + 结果跳转
- 依赖：M0、M1

### M6 一致性检查
分两层，先确定性后模型：
- **确定性检查（规则）**：引用不存在 id、别名冲突、章节缺号/重号、时间线倒序、伏笔未回收、视角人物未在 `characters` 中、目标字数严重偏离
  （2026-09-12 补：第 15 条 `thread-quote`——伏笔记下的 `plantedQuote`/`payoffQuote` 在它记录的那一章里找不到了。它是 `12` §4 欠账的兑现，不是新需求；见 `07` §1.1、`13` §1.4）
  （2026-09-16 补：第 16 条 `context-ref`——章节的 `contextChapters`（参考章节）指向不存在的章算错误、指向已存档的章算警告、写成本章自己算提示。它不是新需求，是 v0.38「上一章全文 + 参考章节进 prompt」的配套：一个手写错的章节 id 只会让 prompt 安静地少一章正文；见 `07` §1.1、`03` §3.2）
- **模型检查**：把相关设定卡 + 章节正文喂给模型，输出结构化 issue 列表（`severity / 章节位置 / 冲突依据 / 建议`）
- 交互：检查结果面板，点击跳转到对应正文位置；可忽略某条
- 落盘：报告写 `.novel/runs/`，忽略项写 `.novel/index.json`
  - **修正（2026-09-11，P3 实施时）**：忽略项改存 `.novel/checks.json` 并进 git——`index.json` 被格式真源定义为可重建、不进 git 的缓存，而「这条我认了」是作者的决定（见 `03` §4.7）；报告**不自动写**，作者点「保存报告」才落到 `.novel/runs/`（见 `07` §2.1）。
- 依赖：M1、M3、M5

### M7 修改记录
- 能力：记录每次修改（包括新增、删除、修改）；可对比不同版本，支持回滚(Ctrl+Z)
- 交互：面板查看修改记录，点击跳转到对应正文位置
- 落盘：`.novel/history/<章节 id>/<时间戳>.json`（存 `before`/`after` 全文与任务来源）
- 依赖：M0
- 备注（2026-09-11 修正）：原写「依赖 M6、M3、M5」「落盘 `chapters/**/*.md`（diff 格式）」——版本历史是编辑器地基能力，不该等一致性检查，故依赖改为 M0；diff 文件放进正文目录会污染章节树，故改到 `.novel/history/`。与 D10 的边界：git 提交是**文件级**历史（每章一次落盘），M7 是**面板内的行级** diff 与回滚。
- **实施记录（2026-09-12，见 `docs/11-m7-history.md`）**：已完成。三处对本文的偏差，理由都写在 `03` §4.9 与 `11` §2：①目录按**文档路径**分家而不是按章节 id（M7 覆盖的不只有章节，且章 id 与卡 id 会撞车）；②回滚写某一版的 **`after`** 而不是 `before`（新建那一版没有 `before`，写回去会得到没有 frontmatter 的空文件）；③**`Ctrl+Z` 绑在「修改记录」页签里**而不是编辑器上——正文 `textarea` 上的 Ctrl+Z 必须留给浏览器自己的逐字撤销，抢过来等于在「撤销」的名义下丢掉未保存的笔迹。全局快捷键策略留给 P5 的「快捷键」那一块。

### M8 导出（P5 补记）

需求 §7 的 P5 一行写着「导出、快捷键、性能、错误处理」，但正文没有给导出单列一节。它按 §2.2 的边界实现：**一个文件一本书**（md 或 txt），范围可选全书 / 某一卷 / 当前章，产物落在 `exports/`（格式真源 §4.10），也可以直接从面板下载。EPUB / PDF / 投稿格式仍是 §9 的后续版本。

- **实施记录（2026-09-12，见 `docs/13-p5-polish.md`）**：已完成（性能那一块见 `docs/10-p5-performance.md`）。**导出**按 §2.2「v1 只做 md / txt」落地：host 渲染整本（`src/novel/book-export.ts`，纯函数），`GET /api/novel/export` 拿预览与下载用的同一个字符串，`POST` 写进 `03` §1 早就定义的 `exports/`（派生、不进 git，也不是可编辑文档，所以不进 M7 的记录）；范围取全书 / 某一卷 / 当前章，只导没存档的章、不带 frontmatter、txt 与 md 正文逐字相同、文件名带时间戳。**快捷键**收成 `src/client/shortcuts.ts` 里一张数据表（`Ctrl+S` 保存「面板认为你在看的那份文档」、`Ctrl+Alt+1..8` 切页签、`Alt+↑/↓` 翻章、`Esc` 取消），只挂在面板根节点上、修饰键完全匹配、备忘单从同一张表渲染；**`Ctrl+Z` 不动**，`11` §2.4 的偏差保持。**错误处理**：状态行分成功/失败两种语气并带上 host 的错误码，连不上 host 时说的是「哪个路由没有得到任何响应、该怎么办」（而不是 `Failed to fetch`），失败旁边有「重试」（`run` 多一个 `redo` 参数，避免重跑捕获了旧缓冲的闭包），有未保存改动时关页面前会问，**修改记录写入失败不再是只进日志的半真话**（`warning` 一路上报到面板，`11` §5 的那条欠账就此结清），修改记录读取失败也不再谎报「没有记录」。

## 5. 统一的 AI 任务模型

所有 AI 能力共用一套约定，避免每个功能各写一套提示词逻辑：

```
任务定义(task) = 输入装配(读哪些设定/大纲/前情) + 提示词模板 + 输出结构 + 落盘策略
```

- **输入装配显式化**：每个任务声明它读哪些文件（如「生成第 12 章」读：本书主线、卷纲、第 12 章章纲、出场角色卡、前 2 章摘要、style-guide）。面板上可展开查看「这次喂了什么」。
- **模型**：复用当前会话的供应商与模型。
- **输出**：正文类任务流式输出到预览区；检查类任务输出结构化 JSON 后渲染。
- **留痕**：每次执行写 `.novel/runs/<时间戳>-<任务>.json`（输入清单、提示词、原始输出、耗时），可重跑、可对比。
- **不静默改写**：任何落盘都要作者确认一次（除非显式勾选「直接写入」）。

## 6. 技术架构（已由 P0-0 spike 验证并定稿）

> 依据：`docs/01-spike-findings.md`。以下每一项都在真实 DSH 实例上验证过，不再是假设。

| 部分 | 机制 |
|---|---|
| 打包形态 | 独立包 `dsh-ai-novel-copilot`：`dsh.bundle.patch` 提供 host 层，`dsh.client`（`platform: 'web'`）+ `exports["./client"]` 提供浏览器层 ✅ 实测可加载 |
| 构建 | 自写 tsdown 双产物配置复刻 DSH 的闭包工厂协议（DSH 自带预设只认 monorepo 内的包） ✅ |
| **读通道** | 复用现成 Remote：`ctx.remote.workspaceFiles.list/read/stat/readAll`（只读，无写） |
| **写通道** | 自建 `/api/novel/*` Fetch 路由（`ctx.connection.fetch.register`），经受 Host/Origin 信任栅栏；**不经**自定义 Remote（其代码生成要求复刻 monorepo 骨架，成本过高） |
| 写围栏 | 写入走 `ctx.fs.writeText` + `ctx.sandboxPolicy.resolve({ session })`，让作者的沙箱策略真正生效 |
| 面板落点 | 右侧边栏 tab：`ctx.sidebarRightTabs.register({ priority: 'extension' })` + `ctx.slots.inject('sidebar.right.pane.tab')`；body 是 session 作用域，直接拿到 `sessionId` |
| 驱动模型 | 面板按钮 → `ctx.sessions.binding(current).session.prompt(...)`（**天然复用当前会话模型**）；流式订阅 `binding.eventSource`；`turn/end.reason` 判定结束 |
| host 半 | 服务（小说工程索引与检索）+ `/api/novel/*` 路由；P1 起可能需要 host 侧 agent/tool 能力 |
| 索引 | 宿主进程内存里的扫描缓存（章节/设定/别名/伏笔的解析结果），按 `ctx.fs` 的新鲜度令牌增量更新（P5，`src/novel/cache.ts`）；**不落盘**，也不做倒排索引（实测理由见 `10` §3.3） |
| 安装 | `dsh plugin --profile <name> add link:E:\GameProject\AI-Novel-Copilot` ✅ 实测通过（**不要用 `file:`**，跨卷会退化成拷贝，见 `01` §2.5） |
| 开发循环 | `pnpm run build`/`watch` + 独立 profile 实例；客户端 bundle 刷新即生效，**host 半必须换进程**（`patchReload: live` 只热重载 `cordis.patch.yml`，不替换插件模块——实测见 `01` §4） |

**spike 已裁决的风险**：客户端通道 ✅ 已解决；bundle 构建链 ✅ 已解决；长文本流式性能 ⚠️ 未验证，推迟到 P1。

**新增的待决策项（P1 前必须定）**：面板 AI 任务是否允许出现在主会话对话记录里（见 `01-spike-findings.md` §3.3 的三条路）。
