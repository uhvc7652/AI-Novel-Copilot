### 1.2 样本怎么进 prompt

```
【文风规则与样本】
<style-guide.md 的内容>

【风格样本（照着这个语感写）】
### sample-a.md
<样本正文>
```

三条规矩：

- **从目录读，不猜**：面板不可能知道作者写了哪些样本，所以用 `/api/novel/dir` 列 `style/samples/`。此前「没接样本」的状态**没有任何报错**，正是因为它连问都没问（§2.1）。
- **上限三份、每份最多 1200 字**：规则是规则，样本是举例——三份读得进去的样本，比十份把本章正文挤出 prompt 的样本有用。
- **按文件名排序取前三**：可预测。作者想换掉哪一份，改文件名即可。

输入清单里逐份列出（`style/samples/sample-a.md — 风格样本（作者认可的段落）`），「这次喂了什么」照旧可展开。

### 1.3 两个新任务

| 任务 | 类型 | 提示词要点 |
|---|---|---|
| **润色本章** | `prose` / `replace-body` | 情节、信息量、人物关系、场景顺序**全部不变**；逐条对照文风规则；规则里的禁用词与 AI 味清单一律不留；句长要有变化；篇幅与原文相当（不要顺手扩写） |
| **去 AI 味检查** | `issues` / `report` | 六类毛病：口头禅与套话、排比与四字词堆砌、段末总结句、形容词副词密度、对话腔调不分人、连接词滥用；每条要给**逐字原文**与**可直接替换或删除的写法**；最多 12 条，宁可少报 |

「润色本章」和既有「改写」的区别是刻意的：**改写**允许模型按自己的判断重做节奏与画面，**润色**被清单和「什么都不许变」这条硬约束绑住——所以它对一章作者本来满意的稿子是安全的。这一点写进了任务的 `hint`。

「去 AI 味检查」的六类毛病里，第五类是需求点名的五类，第六类（连接词滥用）是同一类毛病换了个帽子。**判定标准是样本**：它同时读规则与样本，因为「像不像机器写的」只有对着一个目标才回答得了。

### 1.4 「定位到正文」怎么工作

需求 M4：「问题清单（**可点击定位到正文位置**）」。清单里的每条已经带 `quote`（要求模型逐字复制），所以面板能把它当成锚点：

1. `locateQuote` 切到正文页，并把请求交给一个 effect —— **不能在这里直接选**，因为刚切换时 textarea 还是 `display: none`，拿不到焦点；
2. effect 里先在正文中精确查找那句话。模型凭记忆引用时可能少一个标点或换行，所以退一步做**忽略空白**的匹配，再把扁平下标映射回原文下标；
3. `focus()` + `setSelectionRange()` 选中那句话，用 `scrollHeight / 总行数` 估出行高，把视口滚到那一行上面三行；
4. 状态行说明落在第几行；**找不到就明说**（「没能在正文里找到这句话（模型可能改动过它）」），而不是按了没反应。

没有编辑器的场合（比如检查页上的报告）不显示这个按钮——**一个按不动的按钮比没有按钮更坏**。

## 2. 三个需要记录的决定

### 2.1 一个真缺口：风格样本从来没有进过 prompt

`docs/03-project-structure.md` §4.8 写着 `samples/*.md` 是「生成时的风格锚点」，需求 M4 也写着样本要随任务装配——但从 P1 起，`assembleCommon` 只读了 `style-guide.md`。**没有任何检查会发现这件事**，因为它不是错误：任务照跑，prompt 照生成，只是少了一半的文风输入。这一期把它补上，并在检查脚本里钉住三条（样本进了 prompt、上限三份、第四份连输入清单都不进）。

类似的缺口值得再扫一遍——「文档承诺的输入」与「装配真正读的输入」是两套清单，只有断言能把它们对上。

### 2.2 定位是「选择一句话」，不是「跳到某处」

M5/M6 的跳转都是**换文件**（打开某一章、切到某张卡）。这里第一次出现**文件内定位**，实现选了最笨也最稳的一条：把作者写的那句话选中。理由是 `quote` 已经是逐字复制的要求，而选中即高亮——作者一眼看到的就是模型在说的那句话，不需要再去数第几段。

代价：模型引用不准时定位不了（这时会给一句话说明）。没有做模糊到「第 3 段」级别的兜底，因为一个错位的选中比不选中更容易误导。

> **修于 2026-09-12（M7 期间，见 `11` §4.1c）**：这一节的兜底当年**没有它自己说的那么宽**——注释写「模型可能漏掉一个标点或换行」，代码只忽略空白，因此带上逗号差异的引文一个字都找不到；而且选区结尾是按引文长度加出来的，引文与原文在被忽略的字符上长度不同时会短一截。两处都已修，算法搬到了 `src/client/locate.ts`（纯函数，有测试）。这一段保留，作为当时的记录。

### 2.3 检查类任务现在有两种「落地面」

`issues` 输出现在服务两个不同的任务：`chapter-check`（M6，检查页）与 `style-check`（M4，正文页）。它们的共同点是「报告就是产物、没有采纳」；不同点是前者需要跳到别的文件，后者需要就地选中。所以 `ModelIssueList` 的定位是**可选能力**（有 `onLocate` 才画按钮），而不是写死的行为。这样以后再有第三类检查，只需要决定它有没有可以定位的地方。

### 3.1 检查脚本这一期抓到的

**我的断言写错了对象**：我断言 `styleCheck.place === 'chapter'`，而 `place` 在任务**定义**上、`AssembledTask` 里根本没有这个字段——于是它恒为 `undefined === 'chapter'` 为假。这是本项目第三次踩同一个坑（`05` §3.3 第 2 条、`07` §3.2 第 2 条）。修法是把断言指回 `CHAPTER_TASKS[5].place`。

顺带给渲染检查加了**否定断言**（`!定位到正文`）：只断言「出现」验不了「不该出现」，而条件渲染的 bug 恰好都在后者。

### 3.2 样本装配的断言

- 风格样本进了 prompt（`【风格样本（照着这个语感写）】` + 样本正文）；
- **上限三份**：`sample-d.md` 既不在 prompt 里，也不在输入清单里；
- 输入清单里每份样本的理由是「风格样本（作者认可的段落）」。
- 为此 format-check 的 stub `fetch` 现在也回答 `/api/novel/dir`（按 `FILES` 里真实的目录结构列文件）——替身不会列目录，样本装配就永远只走 catch 分支，这正是「替身也是代码」的又一面。
