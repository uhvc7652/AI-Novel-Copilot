# 伏笔记录：埋下、跳回去、回收

> 格式真源 `03` §4.4 早就定义了伏笔卡与它的生命周期字段（`plantedIn` / `reinforcedIn` / `plannedPayoff` / `payoffIn` / `status`），M6 也有查「埋了没回收」「状态与记录不一致」的规则，检索还能按生命周期作答。
>
> **但面板一个字段都没暴露。** 记一条伏笔 = 先找到（或新建）那张卡、再手改 YAML；从记录回到埋点那一句更是完全没有路。这一期补的就是这一半：**记录入口、跳回去、回收**，全部手动，不经过模型。

---

## 1. 做了什么

### 1.1 三件事，两个入口

| 作者要的 | 入口 | 写下的东西 |
|---|---|---|
| 记一条伏笔 | **正文页**「记为伏笔」：把光标放到那一句（或选中一段） | 新建伏笔卡，写 `plantedIn` = 当前章、`plantedQuote` = 那一句 |
| 跳回埋点 / 跳到回收 | **伏笔页签**每行的两个按钮 | 只读——打开那一章并**选中原句** |
| 回收一条伏笔 | **正文页**「在这里回收」：选一条未回收的伏笔 | `status: paid`、`payoffIn += 当前章`、`payoffQuote` = 那一句（**一次写入**） |
| 放弃一条线 | **伏笔页签**「放弃」 | `status: abandoned`（没有地点，所以归这个页签）——**这条线的名字从此重新可用**（见下） |

「伏笔」页签按 **未回收 / 已回收 / 已废弃** 分三组，未回收默认展开。每行显示：埋点章与原句、计划回收、实际回收章与原句、强化章。

**不要再出现的两条线**（2026-09-12，都是作者点出来的）。面板上有两个「不要了」的动作，它们彼此不同，但有一点一样：**不要了的线不再占名字**。

- **删除 = 存档**（`archived: true`，格式 §4.6 的撤出，入口在「设定」页）。它连卡带页签一起消失，页签顶上写「已删除 N 条」并说明去哪恢复（「设定」页勾「显示已存档」）。
- **放弃 = `status: abandoned`**（本页签的按钮）。卡**留着**（在「已废弃」组，作者要看得见自己丢掉了什么），但这条线不在书里了：名字重新可用，检索不再把它当实体来答，任务装配也不再把它当可用设定。**恢复**（把状态改回未回收）会把这一切都还回来。

作者连着撞了两次：先删掉一条叫「test」的伏笔、再写一条同名的，检查里冒出两条 `alias-clash`；修完存档那一半，他又贴来一条——这次那张卡是**放弃**而不是删除，于是照旧撞车。根因是同一个：**面板、检查、检索、任务四处各自判断「这张卡还算不算数」，其中三处只看 `archived`。** 现在这个判断只有一份：`src/novel/cards.ts` 的 `isRetiredCard()`（`liveCards()` / `liveThreads()` 建在它上面），host 与浏览器共用。理由与两侧代价写在 `07` §2.4。

### 1.2 为什么回收只在正文页做

回收的意义是「**在这一句上收了它**」。原句只能从正文编辑器里取（选区或光标所在行），而伏笔页签里编辑器不在屏幕上。所以那一个动作只放在能拿到句子的地方。

反过来，「放弃」没有地点可言，放在伏笔页签里最顺。

两边都不做的事：**不碰卡片的正文**。`## 埋点方式` / `## 读者应有的疑问` / `## 回收设计` 是作者的散文，面板只写 frontmatter。一张只有骨架的空卡确实不好看，但这是作者领地，`03` 的边界写得很清楚。

### 1.3 `status` 与 `payoffIn` 一起写

M6 有一条规则专门报「status 写着 paid，payoffIn 却是空的」以及反过来。回收时两个字段由面板**同一次写入**，所以那条规则从此只是**给手改的文件兜底的安全网**，而不再是面板逼作者自己去对齐的活。

（这条也正是「面板自己动手」的价值所在：一个只在检查页出现的错误，最好在设计上让它出不来。）

### 1.4 `plantedQuote` / `payoffQuote`：为什么存句子而不是存位置

这是**对格式真源的一处扩展**（`03` §4.4）。存的是那句话本身，不是字符偏移：

- 偏移量会被它**上面任何一个编辑**废掉，而一句话不会；
- 那句话真被改写了的时候，定位会**明说找不到**（面板用的是 M4/M7 那套 `findQuote`），而不是安静地指向「现在占这几个字符的随便什么东西」；
- 一句话可以直接显示在列表里——作者扫一眼就知道这条线埋的是什么，不用打开那一章。

代价是它可能过期（见 §4）。

### 1.5 id 由面板生成：`th-NNN`

在正文里记伏笔时，作者是在给一个**伏笔**起名字，不是在给一个文件起 slug。所以面板自动编号，作者只填显示名。

前缀用 `th-` 而不是 `fs-`：`03` §4.4 那条约定的示例 id 与地点卡示例**都是 `fs-NNN`**，同一份文档里两棵树共用前缀，是读者（和检索）开始分不清它们的方式。`nextThreadId` 只数同形状的 id，所以手写的 `mirror-origin` 既不挡路也不推进序号。

### 1.6 顺手合一的一处重复

`search.ts` 原本自己声明了一个 `SearchThreadLifecycle`，字段与 `CardSummary` 里的伏笔信息重叠但不同源；`io.ts` 里还有一份读 frontmatter 的 `threadLifecycle`。**同一批事实的两份形状**，正是格式禁止的第二种真相——尤其在这一期要**加字段**的时候：漏掉任何一份，伏笔的原句就会在某个消费者眼里消失（比如检索答出「埋于第 1 章」但页签里看不到原句）。

现在只有一个 `ThreadRecord`（`project.ts`），`search.ts` / `checks.ts` / `io.ts` / 面板全部读它。`CardSummary.threadChapters` 那串派生出来的平列表也删了（它是 `plantedIn`/`reinforcedIn`/`payoffIn` 的另一种写法），改成 `threadChaptersOf(record)` 现算。

## 2. 怎么验的

### 2.1 检查脚本（`spike/format-check.mjs`，本节新增 13 条，总计 226）

- **id 生成**：空 → `th-001`；`th-001`/`th-007` → `th-008`；手写的 `mirror-origin` 与 `fs-003` 既不算数也不挡路；`th-100` → `th-101`。
- **章节 id 从路径推出**：`chapters/v01/c0001.md` → `c0001`，非章节路径返回 undefined，多一层目录不算（这条住在 `paths.ts`，因为浏览器也要用，而 `project.ts` 会把 YAML 解析器拖进客户端 bundle）。
- **伏笔记录读得回**：原句、计划、回收章、强化章都在；**没写的字段保持「缺失」而不是空串**（M6 的规则靠这个区分「没填」和「填了空」）；生命周期章节按 埋点→强化→回收 排且去重。
- **「作者指着哪一句」**：有选区取选区、没选区取光标所在行、光标停在换行符上算上一行、空行与「没有编辑器」都不编一个引文出来。这几个用例是把它写成**接受结构化参数**而不是 `HTMLTextAreaElement` 的原因——不用 DOM 就能钉住。
- **io 往返**：写一张带两处原句的伏笔卡，`/cards` 那条路（`library()`）拿到的摘要里原句、状态、回收章、派生章节都在；非伏笔的卡**没有** `thread` 字段（不给每种卡塞一个空壳）。

### 2.2 真实实例（HTTP + 真 `ctx.fs`）

按面板实际做的三步跑（临时探针，已删）：

```
建卡 200 → settings/threads/th-001.md
写埋点 200
面板拿到的：埋点=c0001 原句="他握紧了那半块青铜镜" 状态=planted

写回收 200
面板拿到的：状态=paid 回收章=c0002 回收原句="镜面裂开，露出里面的旧刻痕"

检查页：与这条伏笔有关的 issue 0 条（干净）
检索：伏笔「半块青铜镜的来历」：paid。埋于 第 1 章《第一章》。已回收于 第 2 章。
卡片的正文没被动过：body 里还有骨架分节
```

两件只有真跑才知道的事：**回收之后检查页确实干净**（不是「大概不会报」——`status` 与 `payoffIn` 由同一次写入，M6 的规则读的是同一份记录）；**面板拿到的摘要与卡片文件一致**（原句没有在某一层被丢掉）。

> **一条不是 bug 的观察**：问「青铜镜回收了吗」**答不出来**，问「半块青铜镜的来历」就能答。这是 M5 的既定行为——实体要按**卡片名或别名**命中，而这批查询里的「青铜镜」既不等于卡名也没有登记成别名。给卡加一条 `aliases: [青铜镜]` 就能问。没有改 M5 的匹配规则：放宽成子串匹配会让「随手一问」命中一堆不相干的卡，而 M5 是有意收窄的。

### 2.3 真实 GUI 验证清单（需要作者点）

- [ ] 正文里把光标放到埋点那一句上，点「记为伏笔」，填个名字点「记下」：状态行说清记在了第几章、哪一句。
- [ ] 切到「伏笔」：这条在新的「未回收」组里，埋点章与原句都显示出来。
- [ ] 点「↖ 第 N 章」：回到正文并**选中埋点那一句**。
- [ ] 在正文里把光标放到回收那一句上，下拉选这条伏笔，点「在这里回收」：状态行说清回收在第几章。
- [ ] 再回「伏笔」：它移到「已回收」，回收章与原句都显示；点「↘ 第 N 章」选中回收那句。
- [ ] 去「检查」跑一次：**没有**关于这条伏笔的「状态与记录不一致」。
- [ ] 在「伏笔」里点「放弃」：它移到「已废弃」，未回收的计数减一。
- [ ] 点「恢复」：回到未回收，且**回收章被清掉**（不会留下一个「已恢复但还写着收在哪一章」的矛盾状态）。
- [ ] 选中一整段（跨句）再「记为伏笔」：存下来的是那一整段，跳回去时整段被选中。
- [ ] 正文里一个字都没选中、光标停在空行上：仍然记下章号，只是不记原句（状态行会说明）。
- [ ] 手改一句埋点原句（或把它删掉），再从页签点「跳回埋点」：面板**明说找不到那句话**，而不是跳错地方。
- [ ] 打开伏笔卡的「设定」页：`## 埋点方式` 等分节还是空白——面板没替你写正文。

## 3. 有意不做的

- **不给章节加「本章埋了哪些线」的字段**：格式的单一真相规则（`03` §3.2）写明生命周期**只由卡片记录**。要按章看，用检索或伏笔页签，不落第二个字段。
- **不做「自动发现伏笔」**：需求是「我手动记录」。模型可以提议，但提议要落成作者确认的一条记录才有意义——那是 P5/M5 模型问答的事，不是这一期。
- **不在页签里回收**：见 §1.2。
- **不动 `reinforcedIn`**：「强化」在本期只能手改 YAML。加一个 `reinforcedQuote` 字段是自然的下一步，但需求里没有这个动作，先不加空壳字段。
- **不把原句喂给生成任务**：伏笔的原句进了检索语料（它随卡片正文一起被检索到），但没有单独装配进任何任务的 prompt。要不要「按未回收的伏笔提醒模型」，是任务装配的设计问题，等作者提。

## 4. 已知欠账

- **原句会过期。** 作者改写了埋点那句之后，`plantedQuote` 就指不到东西了：列表里还显示着旧句子，点跳转会失败（会明说）。~~**没有做「原句已失效」的检查规则**——那需要在 host 侧也有一份 `findQuote`（现在它是客户端模块），或者把它挪到一个两边都能用的纯模块里。~~ → **已做**（2026-09-12）：`findQuote` / `lineAt` 抽到 `src/novel/quote.ts`（host 与浏览器共用同一份实现），M6 新增第 15 条规则 `thread-quote`，「检查」页会主动报「埋点/回收原句在当前正文里找不到了」。字段仍然可以手改，也仍然不会跟着正文自动更新——现在只是**有人替你看**。保守之处（原句只有空白不报、回收原句在任一回收章里出现就算还在）见 `07` §1.1 与 `13` §1.4。
- **没有「按章看伏笔」的视图。** 想知道「第 7 章埋了哪些线」，现在只能靠检索或自己扫列表。卡片上没有章的索引，这是 `03` §3.2 的单一真相带来的固有代价。
- **一章里同一位置记两条**不会互相察觉（不去重）。伏笔去重不是一个确定性的问题——两条线可以埋在同一句话上。
- **回收没有撤销按钮。** 但它是 `status` + `payoffIn` 的一次普通写入，所以**M7 的修改记录里有这一版**，可以从修改记录回滚。
- **`plannedPayoff` 只能手改 YAML。** 页签只显示它。加一个「计划在哪回收」的输入框是顺手的事，但这一期没做（作者要的是「回收」，不是「计划回收」）。
- **别名不填，检索就问不出来**（§2.2）：这不是缺陷，但值得在下一步的文档/提示里说一句。
