# 导出、快捷键、错误处理：P5 剩下的三件事

> P5 的三块里，性能那一块上一期就做完了（`10-p5-performance.md`）。这一期补的是另外三件：
> **写完要能交出去**（导出）、**手不用离开键盘**（快捷键）、**出问题要知道怎么办**（错误处理）。
> 三件事各自都不大，但它们合起来才是「日更流程顺手」这句分期标准。
>
> 本期没有动任何已有的存储格式：导出写进格式真源 `03` §1 里早就存在的 `exports/`（派生、不进 git），
> 快捷键是一张纯数据表，错误处理改的是面板怎么说、以及一条此前只进日志的失败怎么被说出来。

---

## 1. 做了什么

### 1.1 导出：两个选择、一条范围、两条出路

| 作者要的 | 入口 | 结果 |
|---|---|---|
| 把稿子交出去 / 自己留一份 | **导出页签** | 选格式（md / txt）与范围（全书 / 某一卷 / 当前章），**预览** → **导出到 `exports/`** 或 **下载** |
| 知道导出去哪了 | 同一个页签下半部分 | 列出 `exports/` 里已有的导出，可刷新 |

**渲染在 host 做。** 面板手里只有卷章树（`ChapterSummary` 是 frontmatter 的摘要，没有正文）；把整本书拼成一个文件需要**每一章的正文与阅读顺序**，那是 host 扫描已经有的事。所以 `GET /api/novel/export` 返回渲染好的整份文本，`POST` 把同一份渲染写进 `exports/`。**预览、下载、写盘是同一个字符串**，不可能三处各说各话。

四条关于「出门时长什么样」的决定：

1. **只导没存档的章。** 存档是格式层面把一章撤出故事（`03` §4.6）：它退出章节树、退出字数、退出任务的材料，那么它也不该出现在交给别人的稿子里。删掉 `archived` 就回来。
2. **frontmatter 不出门。** `id` / `wordCount` / `beats` / `pov` 是机器事实；导出是给人读的。一章里属于「书」的部分是标题与正文。
3. **md 与 txt 只差脚手架，正文逐字相同。** txt 不加 Markdown 装饰（没有 `#`、没有 `>`），也不改写正文：换行重排、全角化、加缩进都是**排版**，不是导出，做了就等于多出第二个版本的稿子（格式的单一真相规则不允许）。
4. **`exports/` 里的文件名带时间戳**（`书名-范围-2026-09-12T06-58-15-501Z.md`）。目录不是版本库（`03` §1），作者改完再导一次应该能在文件管理器里分清哪份是哪份，而不是被静默覆盖。非法字符（`\ / : * ? " < > |`）换成横杠而不是删掉——`第1章:雨夜/前传` 少一个冒号就是另一个标题了。

导出**不进修改记录**：`exports/` 不在 `isDocumentPath` 的白名单里（`paths.ts`），所以它没有编辑面、没有回滚，也不该把作者改过的每一版正文挤出记录列表。

**预览只要开头**（`GET …&head=N`，2026-09-12 补）。一本百万字的书和它的导出差不多大，为了显示 1200 个字而把整本送回来，是这个功能唯一一处浪费。截断发生在**渲染之后**，所以统计（章数、字数）与文件名说的仍是**整份**导出，`bytes` 报的也是全文长度——预览会如实说「全文 N 字节，预览只取开头 1200 个字符」。**写路径永远不接受 `head`**：`exportSpecOf` 只在这条路由的读分支里认它（`allowHead`），因为一个截断的稿子落在磁盘上、还顶着书名，是这个功能最坏的一种 bug；真实实例上专门验了「POST 带 `head=40` → 落盘仍是完整的 146 字节」。

> **一条真跑才发现的问题。** 第一次在真实实例上导出，第二、三章的标题是 `### 第 2 章 第二章 巡夜人`——中文网文的章标题**本来就常自带章号**（连面板的建章表单存进去的也是「第二章 巡夜人」）。检查脚本一条都没报，因为断言里我写的标题恰好不带章号；把真实输出读一遍才看见。
> 现在 `stripChapterNumber` 只在**前缀的数值等于该章章号**时摘掉它（`第十二章` / `第12章` / `第 3 节` 都认，中文数字走 `chineseNumber`），数值对不上就一个字都不动：`第三章` 出现在第 5 章是**书里的事实**，删掉它等于把矛盾藏起来，而不是报出来。

### 1.4 顺手结清的另一条欠账：M6 会报「原句找不到了」

`12` §4 的第一条欠账是「伏笔的原句会过期，而没有对应的检查规则」，理由是它需要在 host 侧也有一份 `findQuote`。做法就是把它挪出来：

- **`src/novel/quote.ts`（新）**：`findQuote` / `lineAt` / `lineNumberOf` 与那套「标点与空白不敏感」的兜底。`client/locate.ts` 只做转发（`export { findQuote, lineAt }`），所以既有 import 一个都没改。**为什么必须共用一份**：检查如果用自己那套「同一句话」的判断，就会出现报告说原句失效、而旁边「跳回埋点」按钮照样选中的矛盾——那种报告没人会信。
- **M6 新增第 15 条规则 `thread-quote`**（`07` §1.1）：伏笔卡记下的 `plantedQuote` / `payoffQuote` 在它记录的那一章正文里找不到了，报一条警告，依据两侧（卡片字段 + 那一章），点「打开」进卡片页。
- 两处**有意保守**：`plantedQuote` 只有空白时不当成「找不到」（那是「还没填」，不是「过期了」）；`payoffQuote` 在 `payoffIn` 列出的**任何**一章里出现就算还在（面板只写一章，但手改的卡可能列好几章——列出来的每一处都找不到才叫找不到）。
- 为此章节正文进了 `CheckCorpus`：`scanChapterTexts` 本来就把它读出来了（检索要用），规则拿到的只是同一份数据，不额外读盘。

### 1.2 快捷键：一张数据表，三条规则

| 键 | 做什么 |
|---|---|
| `Ctrl+S` | 保存**面板认为你在看的那份文档**（正文 / 设定卡 / 卷纲或章纲） |
| `Ctrl+Alt+1`…`8` | 切到第 1…8 个页签（顺序即 `ui.ts` 的 `PANEL_SECTIONS`） |
| `Alt+↑` / `Alt+↓` | 上一章 / 下一章（走 `loadChapter`，所以**未保存提示照旧**） |
| `Esc` | 关掉「记为伏笔」表单，或清掉状态行上的失败提示 |

`src/client/shortcuts.ts` 是纯数据 + 纯匹配（`actionFor`），面板只是把 `onKeyDown` 挂在**面板根节点**上。三条规则各有明确理由：

- **每条绑定都带修饰键。** 这一套里没有任何「无修饰键的可打印字符」，所以不存在「得先判断焦点是不是在输入框里」这个问题：`Ctrl+Alt+1` 不会变成正文里的一个 `1`。检查脚本把这条写成了断言。
- **修饰键必须完全匹配。** `Ctrl+Shift+S` 不是保存，`Ctrl+Alt+9` 没有绑定。差一点就悄悄做了别的事，比什么都不做更坏。
- **键是公开的。** 快捷键备忘单（页签行右边的「快捷键」）由绑定表**渲染**出来，按钮的 `title` 也取自同一份表，所以不存在「文档说 Ctrl+S、代码听 Ctrl+J」。

几处刻意的选择：

- **`Alt+↑/↓` 而不是 `Ctrl+←/→`**：横向那一对在很多外壳里就是「后退 / 前进」，把作者的返回键肌肉记忆花在「下一章」上，是快捷键变成丢工作的一种方式。纵向一对里，上是树的上方，和章节树读的方向一致。
- **`Ctrl+Z` 一动不动。** 正文 `textarea` 上的 `Ctrl+Z` 仍然是浏览器自己的逐字撤销（M7 的偏差，`11` §2.4 的理由不变），回滚仍在「修改记录」页签里。
- **只挂在面板根节点，不注册全局监听。** 焦点不在面板里时，这些键对外壳和浏览器**完全不存在**——插件没有资格替整个 GUI 决定 `Ctrl+S` 是什么意思。
- **`Ctrl+S` 保存的是 `activeDoc`**（M7 收在一处的「作者在看哪份文档」），所以焦点在卡或大纲上时，保存键保存的是那张卡/那份大纲，而不是屏幕外的章节。跨 surface 走 `saveToken`（与 `refreshToken` 同形），三个编辑器的保存逻辑不必上提。

### 1.3 错误处理：失败要看得出来、说得出、重得来

| 之前 | 现在 |
|---|---|
| 失败与成功是同一行灰字，只差措辞 | 状态行带 tone：失败是红色，且按钮不会被变暗的样式包住（`client-load-check` 的样式规则仍在守） |
| 只有一句中文 | 附上 host 的稳定码（`novel/outside-project`、`FS_PERMISSION_DENIED`…）——它说的是哪一层拒绝，中文句子说不出来 |
| 浏览器抛 `Failed to fetch` | `novel/offline`：说清**哪个路由没得到任何响应**、实例可能刚重启、刷新页面再试 |
| 失败之后只能自己重做整件事 | 状态行旁边一个**重试**按钮 |
| 有未保存改动时，切章/切卡会问，关标签页不问 | 关页面前 `beforeunload` 也会问（文案由浏览器决定，我们只能决定「问不问」） |
| 修改记录写失败只进日志（`11` §5 的欠账） | 写进 `warning` 一路带到面板：**「文件已保存，但这一版不能回滚」** |
| 修改记录读失败时，页签说「这个文件还没有被面板保存过」 | 说「修改记录读不出来：<原因>」——空列表和问不出来是两件事 |

两条实现上的注意：

- **重试不能重跑那个失败的闭包。** 保存的闭包**捕获了失败那一刻的缓冲**，失败之后作者又写了一段的再点重试，就会把**旧稿**写下去。所以 `run(label, operation, redo)` 多了一个 `redo`：写编辑器状态的三条路径（正文 / 卡 / 大纲）传一个**重新取当前状态**的 redo（`saveActive` / `onSave` 经 ref 取最新），其余操作（打开、扫描、导出、回滚到某一版）**重跑的是失败的那一次调用**——对扫描与回滚这就是同一件事，而对「导出」「打开工程」这类**参数活在面板状态里**的操作不是：失败后把格式/范围（或工程目录）改了再点重试，重跑的仍是失败那一刻的参数，而不是屏幕上的这一份——做的是「重做旧的那一件事」，不会写坏稿子，但也不再是作者眼下想要的那一件。这条在文档里写下来，是因为它是「看不见的那一半」：正常路径永远正确。
- **半失败要有它的语法。** 正文已经落盘、撤销的那一版没写进去——这不是错误（保存成立），也不是成功（路少了一条）。`WrittenChapter`/`WrittenDocument` 因此多了一个可选 `warning`，面板照原样显示。这也是本期唯一一处对既有返回类型的扩展。

## 2. 怎么验的

### 2.1 检查脚本

`spike/format-check.mjs` 新增 **54** 条（40 条在本期主体，14 条在 §1.4 与下面这份清单的末尾；总计 **280**）：

- **导出渲染**：md 的书名/概览/卷章分层、txt 没有 Markdown 装饰、两种格式正文逐字相同、存档章不出门、没有标题的章仍有章号、frontmatter 与机器字段不出门、正文两侧空白收掉但正文逐字保留、卷范围不重复卷标题、单章范围没有书名页。
- **章号前缀**：`第十二章`/`第12章`/`第 3 节` 都摘（中文数字 `二十三`、`一百零三` 也对），**与章号不等时一个字都不动**，`第十个夏天` 这种看着像但不是的不动，只有章号时剩下干净标题。
- **文件名**：`书名-范围-时间戳.md` 的形状、非法字符变横杠、空书名兜底。
- **拒绝路径**：不存在的章 / 已存档的章 / 空书 / 空卷各自明说为什么（而不是导出一份空的）。
- **host IO**：`exportBook` 含刚写的正文、`saveExport` 写进 `exports/` 且读回与渲染一致、**导出不在可编辑白名单里也不产生修改记录**、`ExportError` 被翻译成 `novel/bad-request`。
- **半失败**：让 `.novel/history` 的写入被拒绝（内存 fs 替身按路径抛 `FS_PERMISSION_DENIED`），断言正文真的落盘了、警告里说清「不能回滚」、而正常写入**没有**警告（不能把「都正常」也说成有事）。
- **快捷键**：`Ctrl+S`（含 `S` 与 `⌘`）、`Ctrl+Alt+1..8` 与 `PANEL_SECTIONS` 逐位对应、多一个修饰键就不匹配、没绑过的键落空、`Alt+↑/↓`、`Esc` 只在无修饰键时、每个动作都能印出它的键且键不重复、**没有一条是无修饰键的可打印字符**。
- **错误文案**：`fetch` 抛异常时说「没能连上 DSH host」+ 路由 + 刷新页面 + 原始信息，并带 `novel/offline` 码。
- **预览截断**（§1.1）：不给 `head` 时 `bytes` 等于文本长度、`truncated` 为假；给了 `head` 只有开头那么多，而统计与文件名仍是整份导出的；`head` 比全文大不算截断；`head` 是 0/负数/NaN 时当成没给。**截断不许出现在写路径**这一条在真实实例上验（§2.2）。
- **原句查找**（§1.4）：host 直接 import `novel/quote.ts` 拿到的 `findQuote` **就是** `locate.ts` 转发的那一个（同一个函数引用，不是两份实现）；`lineAt` / `lineNumberOf` 的坐标一致；空引文返回 `missing`。
- **`thread-quote` 规则**（§1.4）：原句还在→不报；被改写→报一条 warn（key 是 `thread-quote:<卡路径>:plantedQuote:<章 id>`，两侧依据都在）；**标点差异仍算找得到**；回收原句在任一回收章里→不报；哪里都没有→报一条且依据里列出找过的每一章；原句字段只有空白→不报；整条规则在这份 fixture 里恰好只报两条。

`spike/client-load-check.mjs` 新增 **2** 次渲染（总计 **17**）：导出页两态（默认；打开了一章且未保存时，必须出现「导出不会带上它」）。`dimmed-control rule: 11 view files clean` 仍然全绿——重试按钮是变暗文本的**兄弟节点**，不是子节点。

> **本节里的「总计」是当天的数**（280 项 / 17 次渲染 / 11 个视图文件）。这一期之后又做了几轮（`07` §5 记的 288、设定页的两处、以及列表输入与 `role` 那一轮），检查是只增不减的，所以**当前值以 README 的 `pnpm run check` 一行为准**（2026-09-12 晚：331 项 / 21 次渲染 / 13 个视图文件）。具体数字会继续变，这句说明不会。

### 2.2 真实实例（HTTP + 真 `ctx.fs`）

`.spike-novel` 上跑（临时探针，已删）：

```
ping: /api/novel/export 已在运行中的 host 路由表里（14 条）
GET  全书 md ：测试之书-全书-2026-09-12T06-58-15-501Z.md · 3 章 · 58 字
      # 测试之书 / 中文长篇网文 · 共 3 章 · 约 58 字
      ## 第 1 章 御剑 / ## 第 2 章 巡夜人 / ## 第 3 章 青铜镜
GET  全书 txt：没有 '#'
GET  第 1 卷  ：3 章 · label=第 1 卷
POST 全书 md  → exports/测试之书-全书-2026-09-12T06-58-15-542Z.md（146 字节）
      读回的内容与 GET 逐字相同
dir exports/  ：exists=true，三个文件（三次导出三份，没有互相覆盖）
dir .novel/history/exports：exists=false（导出不是文档，没有版本）
POST 不存在的章 → 400；POST 没有 volume 的卷导出 → 400
```

三件只有真跑才知道的事：**章标题叠号**（§1.1 末，已修，第一个进程上还是 `第 2 章 第二章 巡夜人`）；**导出确实是一次一个新文件**（`exports/` 里三个文件，而不是一个被覆盖三次）；**导出没有留下任何修改记录**（`.novel/history/exports` 根本不存在）。

补做那两条时又跑了一轮（新进程，`head` 与 `thread-quote`）：

```
GET  全书 md            ：text=146 bytes=146 truncated=false chapters=3
GET  …&head=40          ：text=40  bytes=146 truncated=true  words=58（整份的统计）· 文本是全文的前缀
GET  …&head=999999      ：text=146 truncated=false
POST 全书 md {head:40}  → exports/…md，bytes=146
     读回磁盘上的文件：146 字符，与完整导出逐字相同（**写路径确实不认 head**）
checks：thread-quote 1 条
  [warn] thread-quote:settings/threads/th-901.md:plantedQuote:c0001
         伏笔「探针伏笔：原句已过期（故意写坏）」的埋点原句在当前正文里找不到了
         settings/threads/th-901.md · plantedQuote: 他握紧了那半块青铜镜
         chapters/v01/c0001.md · 第 1 章《御剑》 里找不到这一句
把 th-900 的原句改成「他御剑而起转瞬掠过屋脊」（正文里是「他御剑而起，转瞬掠过屋脊。」）→ 再跑 checks：thread-quote 0 条
```

**跨了 host/client 的那一条**（标点差异仍算找得到）只能靠真跑证明：检查页给的是「没意见」，而面板的「跳回埋点」在同一个实例上也选得中那一句——两边用的是同一个函数（`quote.ts` 的 `findQuote`），这正是把它抽出来的理由。

> 环境事实（这轮踩到的）：`pnpm run build` 之后 **host 半必须换一个新进程**才认得新路由/新规则——第一次探针跑在旧进程上，`/api/novel/export` 还不存在；改成一个新进程之后才是上面这份结果。这与 README「环境事实」第 1 条是同一件事，只是这次撞在导出上（补做那轮又撞了一次：新规则在旧进程里根本不会出现）。

### 2.3 真实 GUI 验证清单（需要作者点）

- [ ] 打开一本有正文的工程，点「导出」页签：默认是 Markdown + 全书，预览一段开头，字数与章数对得上工程信息。
- [ ] 点「导出到 exports/」：状态行报出路径；用文件管理器打开工程的 `exports/`，文件在，内容与预览一致。
- [ ] 再点一次「导出到 exports/」：**多出一个文件**，不是覆盖。
- [ ] 点「下载」：浏览器下载那个文件名；打开确认正文完整（预览只显示开头 1200 字，下载的是全文）。
- [ ] 把格式切成「纯文本（.txt）」再导出：没有 `#`，章标题是纯文本行。
- [ ] 范围切「某一卷」「当前章」各导一次：卷导出只含那一卷，单章导出没有书名页。

## 3. 有意不做的

- **不做 EPUB / PDF / 投稿格式**：需求 §2.2 写死了「v1 只做 md / txt 导出」，EPUB 在 §9 的后续版本里。
- **不导出设定卡与大纲**：导出的是**书稿**。设定卡是写作时的工作台，投稿要的是正文；真要备份整个工程，就是复制目录或 git。
- **不改写正文**（不重排换行、不转全角、不加缩进、不解析 Markdown）：那是排版，不是导出；做了就有第二份「处理过的稿子」。
- **不做多文件导出**（一卷一个文件、一章一个文件）：投稿要的是「一个稿件」，「导出」这个动作一旦产出一堆文件就不再是一个可以交出去的东西。
- **不做全局快捷键**：只在焦点位于面板内时生效，不抢外壳与浏览器的键。
- **快捷键不可自定义**：先有能用的默认值，配置项等作者真的想改再说（多一个设置界面就是多一处要维护的真相）。
- **不给导出做清理 / 上限 / 翻页**：`exports/` 是作者自己的目录，面板只列最近 12 个；删除由作者在文件管理器里做（`ctx.fs` 也没有删除原语，`03` §4.6）。
- **不给重试做队列**：一次只记最后一个失败，重试成功即清空。

## 4. 已知欠账

- **~~`GET /api/novel/export` 返回全文~~ → 已修（2026-09-12）**：加了 `head` 参数，预览只取开头 1200 字符（统计与文件名仍是整份的，写路径不接受它）。剩下的只是「渲染整本才能在预览时给出准确字数」——一本百万字的书仍要在 host 侧拼一次全文再截断，省掉的是网络与面板内存，不是渲染。
- **重试的 `redo` 只覆盖写编辑器状态的三条路径**：其余操作重跑的是失败时那一次调用。对扫描与回滚而言那就是同一件事；对**参数在面板状态里**的操作（导出、打开工程）则不是——失败后改了选择再点重试，重跑的仍是失败那一刻的参数。「重试」并不是对每个操作都语义精确。
- **下载走 Blob + `<a download>`**：无 DOM 的环境不能用（会说），且浏览器**不会告诉你下载是否成功**——这与「写进 `exports/` 后能读回」相比是弱一档的承诺。
- **`novel/offline` 是客户端造的码**，host 侧没有对应物；host 的错误码稳定，客户端的这一条只是面板自己的约定。
- **`beforeunload` 的文案改不了**：只能决定问不问。
- **章的标题里带章号时，面板其他地方仍然会叠**（章节树与模型检查的标题都是 `第 N 章 {title}`）：本期只修了导出这一处，因为导出是「交出去」的那一份；树里叠不叠是显示习惯问题，改它要动面板的三处文案。
- **原句过期只报，不修**：`thread-quote` 说明「这句话找不到了」，但不会替作者把 `plantedQuote` 改成现在的那一句——哪一句才是这一条线，只有作者知道。
- **旧账不在此期**：M5 的模型问答、段落级润色、伏笔无「按章看」视图（原句过期那一条已在 §1.4 结清）、模型两轮与页面交互的人工验证（都在 README 的欠账里）。
