# AI-Novel-Copilot

一个 **DSH（DeepSeek Harness）Web 插件**：把 DSH 变成中文长篇网文的写作台——左侧一个「小说」入口，右侧一个写作面板，工程以纯 Markdown 存在工作区里，AI 生成一律先进预览、由作者采纳后才落盘。

> 本文件是**入口**。需求的唯一真源是 `docs/00-requirements.md`，磁盘格式的唯一真源是 `docs/03-project-structure.md`。

├── novel/                host 半

│   ├── project.ts        工程布局、卷章树（**卷纲存在即一卷**：`mergeVolumes`）、卡摘要与反向索引、章号（**全书连续**，`nextChapterNumber`）、脚手架

│   ├── history.ts        **M7 修改记录（纯模块）**：行级 diff、折叠、动作判定、条目解析

## 开发

```sh
pnpm install
pnpm run check          # typecheck + build + format-check + client-load-check，改完跑这个
pnpm run typecheck      # 只跑 tsc --noEmit
pnpm run build          # 产出 lib/index.js（host）与 lib/client.js（浏览器）
pnpm run watch          # 开发期增量构建
```

安装进 DSH profile —— **必须用 `link:`，不要用 `file:`**：

```sh
node <dsh>/apps/cli/lib/bin.js plugin --profile <name> add link:E:/GameProject/AI-Novel-Copilot
```

> ⚠️ `file:` 在**跨卷**时退化成拷贝（本机：源码在 E:，profile 在 C:），profile 会冻结在安装那一刻，之后所有重建都到不了 GUI，而界面上毫无提示。详见 `docs/01-spike-findings.md`。
>
> ⚠️ 用 `link:` 之后仍然有一半要换进程：**浏览器半刷新页面即生效，host 半（新路由、新行为）必须起一个新进程**。DSH 的 `patchReload: live` 只热重载 `cordis.patch.yml`，不替换插件的 JS 模块（源码证据与判定方法见 `docs/01-spike-findings.md` §4）。面板里新加的路由报 404 时，先看 `/api/novel/ping` 返回的 `routes` —— 那就是运行中的 host 半真正注册了哪些路由。

启动（开发用隔离实例，不动日常 profile）：

```sh
$env:DSH_HOME='E:\GameProject\AI-Novel-Copilot\.dsh-home'
$env:DSH_NOVEL_ROOT='E:\GameProject\AI-Novel-Copilot\.spike-novel'
$env:DSH_PERMISSION_MODE='danger-full-access'
node <dsh>/apps/cli/lib/bin.js --profile novel --no-open --port 3099
```

> `pnpm dsh`（= `node --import tsx/esm`）在受限沙箱下会因 esbuild 子进程 `spawn EPERM` 失败，改用已构建的 `apps/cli/lib/bin.js`。

## 运维脚本（`tools/`，作者自己在终端里跑）

面板的能力面里没有删除、也没有重命名/移动（`ctx.fs` 只有 resolve/stat/lstat/list/read/write/edit），所以「把已存档的文件清掉」「把已存档的文件改名藏起来」这两件事做成脚本——**它们跑在你的终端里，用的是你的权限**，与插件不越沙箱那条原则不冲突：那是你在动自己的文件。

**双击就能用**（不想开终端的话）：`tools/archive-delete.cmd` 与 `tools/archive-suffix.cmd`——双击，或者在资源管理器里**把小说工程目录拖到它上面**。它们会：切到 UTF-8 代码页 → 跑脚本 → 让你在脚本里输路径（拖了就免输）→ 先给你看预演 → 问一句「现在真的做吗？」→ 做完 `pause` 等你按键。**不是终端（管道/重定向）时永远停在预演**，所以同一个文件放进脚本里跑也不会自己动手。

```sh
# 终端里的用法（默认预演，不加 --apply 不动磁盘）
node --experimental-transform-types tools/archive-delete.mjs   <小说工程目录>
node --experimental-transform-types tools/archive-suffix.mjs   <小说工程目录>
node --experimental-transform-types tools/archive-delete.mjs   <小说工程目录> --apply
node --experimental-transform-types tools/archive-suffix.mjs   <小说工程目录> --apply
node --experimental-transform-types tools/archive-suffix.mjs   <小说工程目录> --restore --apply

# 或者用 package.json 里的别名（参数直接跟在后面，不要写 --）
pnpm run archived <小说工程目录> --apply
pnpm run archived:suffix <小说工程目录> --apply
```

> **`.mjs` 不能双击运行**：Windows 上没有关联时双击只会让你「选择打开方式」，就算关联到 `node.exe`，双击时**没有参数**、黑窗口**一闪就关**，而这两个脚本必须要一个工程目录。所以双击入口是 `.cmd` 包装（上面那两个），交互提示全部放在 Node 脚本里。

| 脚本 | 做什么 | 关键设计 |
|---|---|---|
| `archive-delete.mjs` | 删掉工程里所有 `archived: true` 的文件 | **预演是默认**（要 `--apply` 才动盘）；动手前逐条列出**删了会有什么后果**——哪些文件的 frontmatter 还提到这个 id（那些引用会变成 `missing-ref` / `thread-ref` / `timeline-ref`）、这一章的章号后面还有没有章（有的话删掉会报 `chapter-gap`）；只碰 `chapters/ settings/ outline/ style/` 这四棵树，不动 `.novel/` 与 `exports/` |
| `archive-suffix.mjs` | 给已存档的文件加后缀（默认 `.archived`），或 `--restore` 去掉 | 后缀加在**扩展名之后**（`c0009.md` → `c0009.md.archived`）：名字一旦不以 `.md` 结尾，插件就完全不读它（章节按扩展名找、卡片按 `settings/<类型>/<id>.md` 找）；`c0009.archived.md` 那种写法会被当成新章节扫描到并立刻报 `id-mismatch`，所以脚本直接拒绝以 `.md` 结尾的后缀 |
| `archive-delete.cmd` / `archive-suffix.cmd` | 上面两个脚本的**双击入口**：双击、或把工程目录拖上去 | 只做三件事：`chcp 65001`（中文输出）→ `node <脚本>` → `pause`；**所有交互提示都在 Node 脚本里**——因为 `chcp` 之后 cmd 的 `set /p` 读重定向输入会失效，把提示写在批处理里正好是错的（这条是实测出来的，见「环境事实」第 4 条） |

两个脚本都只认 `archived: true`（YAML 布尔，用插件自己的 frontmatter 解析器读，不是第二套正则），都会拒绝看起来不像小说工程的目录（路径给错了代价很大），改名遇到同名文件时跳过而不是覆盖。删掉的内容仍然躺在 `.novel/history/<文档路径>/` 里（面板保存过的每一版全文）以及 git 里。

## 八条设计上的教训（都写进了文档）

1. **执行器绝不能是「当前会话」。** 第一版把提示词发进作者与编码 agent 的同一个会话，结果"小说续写"由编码 agent 回答——留痕里躺着的是聊天记录而不是正文。现在每次任务在 host 侧新建一个独立的一次性子代理：空历史、`systemPrompt.section({ complete: true })` 让写作指令成为**完整**系统提示词、`tools.restrict({ allow: [] })` 禁掉工具（怎么让它不出现在侧栏见第 4 条）。
2. **有类型检查却不跑，等于没有。** 一个「按钮恒灰」的低级错误漏到了作者手里。运行期渲染检查抓不到它——组件渲染通过，但那段 JSX 一次都没被执行。
3. **被能力面挡住的请求，要么降级要么明说，不要绕过围栏。** `ctx.fs` 没有删除原语（resolve/stat/lstat/list/read/write/edit，仅此而已），所以「删卡」和「删章」都实现为 `archived: true` 存档——章节还额外保留 id 与章号，恢复时不撞引用——而不是拿 `node:fs` 去 unlink：沙箱策略是作者对自己文件说的话。同理，检查脚本要么跑真模块（`--experimental-transform-types` 直接 import `.ts`），要么在注释里写清它抄了什么、为什么可以抄。
4. **没验证的假设不要写成「所以」。** P1 记下「不设 `cwd` → 不进作者侧栏」，后果是每次任务都在侧栏留下一条打不开的会话（`session/not-found`）。DSH 里隐藏会话的开关只有一个：header 的 `origin: 'subagent'`。现在写作子会话按 DSH 自己的一次性子代理创建（`origin` + `parentSession` + `subagent/descriptor`），提示词走子会话自己的 `followup`——因为 Session API 正是用 `agent-busy` 拒绝按普通 id 驱动子代理的。
5. **断言证明你想到的事，读一遍真实输出才能发现你没想到的事。** M5 的检索检查全绿之后，我把引擎输出原样打出来读了一遍，立刻发现「是哪章」被当成了检索词、剥剩一个「过」字导致**每一章都算命中**——两条都被断言漏掉了（`06` §3.2）。同一个教训在 P5 的导出上又应验一次：断言里的章标题恰好不带章号，真实实例导出的却是 `第 2 章 第二章 巡夜人`——中文网文的标题本来就常自带章号，只有把真实输出读一遍才看得见（`13` §1.1）。检查脚本是防止回归的，不是发现自己没想到的东西的。
6. **降级路径也是一条路径，不写测试就等于没有。** P5 的扫描缓存有三条降级：列举带令牌 / 不带令牌退 `stat` / 哪里都没有令牌就不缓存。第三条我写成了 `continue`——不是「不缓存」，是**根本不读这个文件**，整个工程在那种后端上会静默变成空书。`format-check` 里那条「宁可每次重读」的断言当场变红（`10` §4.1）。降级分支比主分支更容易写错，因为它平时不跑。
7. **尺子也要先量一遍。** P5 的基准替身漏了 `dsh-fs-local` 列举时对**每个子项**做的 `realpath`（Windows 上一次约等于八次 `stat`），把暖扫描量快了 9 倍，据此写下的「10–14×」是错的；真实实例一跑就露馅（`10` §1.3）。替身也是代码——它错的时候不报错，只是安静地把最重要的成本算成零。同一轮里「拿目录令牌跳过列举」也被自己的探针否掉：单次采样两次给出相反答案，20 轮速率才看清它只是个**延迟落地**的信号（`10` §3.4）。
8. **浏览器半的能力面是外壳那份冻结模块表。** 客户端 bundle 里的 `require` 只有表里那 9 个平台模块能被回答，**别的必须在打包时内联**——多一条就是插件**加载即抛**、面板整个不出现，不是慢一点。这一条被踩实过：把一个比较函数放进 `novel/document.ts`（那个模块 import 了 YAML 解析器），三个客户端文件一 import，`lib/client.js` 里就多出一条 `require`，作者的插件当场起不来。**而当时全套检查是绿的**——`client-load-check` 在 Node 里跑 bundle，`require` 从 `node_modules` 解析得到，Node 的宽容正好盖住了浏览器的严格。所以现在有第 6 条源码规则：从 `tsdown.config.ts` 读出 `PLATFORM_MODULES`，**剥掉注释**后扫 bundle 里所有 `require("…")`，不在表里就失败。推论写进代码：**凡是两边共用的模块，先问它会不会把 host-only 依赖拖进浏览器**（`quote.ts` / `cards.ts` / `buffer.ts` 就是这么来的）。
