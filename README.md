# AI-Novel-Copilot

一个 **DSH（DeepSeek Harness）Web 插件**：把 DSH 变成中文长篇网文的写作台——左侧一个「小说」入口，右侧一个写作面板，工程以纯 Markdown 存在工作区里，AI 生成一律先进预览、由作者采纳后才落盘。

> 本文件是**入口**。需求的唯一真源是 `docs/00-requirements.md`，磁盘格式的唯一真源是 `docs/03-project-structure.md`。

## 开发

```sh
pnpm install
pnpm run check          # typecheck + build + format-check + client-load-check，改完跑这个
pnpm run typecheck      # 只跑 tsc --noEmit
pnpm run build          # 产出 lib/index.js（host）与 lib/client.js（浏览器）
pnpm run watch          # 开发期增量构建
```

安装进 DSH profile —— **必须用 `link:`，不要用 `file:`**：

```sh
node <dsh>/apps/cli/lib/bin.js plugin --profile <name> add link:E:/GameProject/AI-Novel-Copilot
```

> ⚠️ `file:` 在**跨卷**时退化成拷贝（本机：源码在 E:，profile 在 C:），profile 会冻结在安装那一刻，之后所有重建都到不了 GUI，而界面上毫无提示。详见 `docs/01-spike-findings.md`。
>
> ⚠️ 用 `link:` 之后仍然有一半要换进程：**浏览器半刷新页面即生效，host 半（新路由、新行为）必须起一个新进程**。DSH 的 `patchReload: live` 只热重载 `cordis.patch.yml`，不替换插件的 JS 模块（源码证据与判定方法见 `docs/01-spike-findings.md` §4）。面板里新加的路由报 404 时，先看 `/api/novel/ping` 返回的 `routes` —— 那就是运行中的 host 半真正注册了哪些路由。

启动（开发用隔离实例，不动日常 profile）：

```sh
$env:DSH_HOME='E:\GameProject\AI-Novel-Copilot\.dsh-home'
$env:DSH_NOVEL_ROOT='E:\GameProject\AI-Novel-Copilot\.spike-novel'
$env:DSH_PERMISSION_MODE='danger-full-access'
node <dsh>/apps/cli/lib/bin.js --profile novel --no-open --port 3099
```

> `pnpm dsh`（= `node --import tsx/esm`）在受限沙箱下会因 esbuild 子进程 `spawn EPERM` 失败，改用已构建的 `apps/cli/lib/bin.js`。

## 七条设计上的教训（都写进了文档）

1. **执行器绝不能是「当前会话」。** 第一版把提示词发进作者与编码 agent 的同一个会话，结果"小说续写"由编码 agent 回答——留痕里躺着的是聊天记录而不是正文。现在每次任务在 host 侧新建一个独立的一次性子代理：空历史、`systemPrompt.section({ complete: true })` 让写作指令成为**完整**系统提示词、`tools.restrict({ allow: [] })` 禁掉工具（怎么让它不出现在侧栏见第 4 条）。
2. **有类型检查却不跑，等于没有。** 一个「按钮恒灰」的低级错误漏到了作者手里。运行期渲染检查抓不到它——组件渲染通过，但那段 JSX 一次都没被执行。
3. **被能力面挡住的请求，要么降级要么明说，不要绕过围栏。** `ctx.fs` 没有删除原语（resolve/stat/lstat/list/read/write/edit，仅此而已），所以「删卡」和「删章」都实现为 `archived: true` 存档——章节还额外保留 id 与章号，恢复时不撞引用——而不是拿 `node:fs` 去 unlink：沙箱策略是作者对自己文件说的话。同理，检查脚本要么跑真模块（`--experimental-transform-types` 直接 import `.ts`），要么在注释里写清它抄了什么、为什么可以抄。
4. **没验证的假设不要写成「所以」。** P1 记下「不设 `cwd` → 不进作者侧栏」，后果是每次任务都在侧栏留下一条打不开的会话（`session/not-found`）。DSH 里隐藏会话的开关只有一个：header 的 `origin: 'subagent'`。现在写作子会话按 DSH 自己的一次性子代理创建（`origin` + `parentSession` + `subagent/descriptor`），提示词走子会话自己的 `followup`——因为 Session API 正是用 `agent-busy` 拒绝按普通 id 驱动子代理的。
5. **断言证明你想到的事，读一遍真实输出才能发现你没想到的事。** M5 的检索检查全绿之后，我把引擎输出原样打出来读了一遍，立刻发现「是哪章」被当成了检索词、剥剩一个「过」字导致**每一章都算命中**——两条都被断言漏掉了（`06` §3.2）。检查脚本是防止回归的，不是发现自己没想到的东西的。
6. **降级路径也是一条路径，不写测试就等于没有。** P5 的扫描缓存有三条降级：列举带令牌 / 不带令牌退 `stat` / 哪里都没有令牌就不缓存。第三条我写成了 `continue`——不是「不缓存」，是**根本不读这个文件**，整个工程在那种后端上会静默变成空书。`format-check` 里那条「宁可每次重读」的断言当场变红（`10` §4.1）。降级分支比主分支更容易写错，因为它平时不跑。
7. **尺子也要先量一遍。** P5 的基准替身漏了 `dsh-fs-local` 列举时对**每个子项**做的 `realpath`（Windows 上一次约等于八次 `stat`），把暖扫描量快了 9 倍，据此写下的「10–14×」是错的；真实实例一跑就露馅（`10` §1.3）。替身也是代码——它错的时候不报错，只是安静地把最重要的成本算成零。同一轮里「拿目录令牌跳过列举」也被自己的探针否掉：单次采样两次给出相反答案，20 轮速率才看清它只是个**延迟落地**的信号（`10` §3.4）。

- **真实实例（HTTP）**：`/api/novel/search`（提问 / 关键词 / 空查询）与 `/api/novel/checks`（跑检查 / 忽略 / 保存报告 / 非法动作 400）都跑通了（`06` §3.3、`07` §3.3）。
- **真实 GUI**：任务能跑完并流式出正文、检索能跑通。
- **性能**：`spike/perf-check.mjs` 在真磁盘上量（1000 章 / 311 万字）：snapshot 1340→296 ms、检索 1453→340 ms、检查 1391→345 ms（4–5×，冷启动不变慢）；同一本书在**真实实例**上走 HTTP：1688→330–380 ms。**剩下的时间几乎全在 `dsh-fs-local` 列举时每个子项的 `realpath` 上**（`spike/fs-cost-check.mjs` 拆出来了），插件的能力面里躲不掉——详见 `10` §3.3、§5。**缓存的核心承诺**（面板外改一章，下一次请求就看得见；改回去立刻看不见）已在真实实例上跑通（`10` §4.2），走的是真 `ctx.fs` 与真令牌。
- **修改记录（M7）**：真实实例上跑通「手写保存 → 采纳「润色本章」后保存 → 列表 → 行级 diff → 回滚 → 读回」（`11` §4.2）。三件只有真跑才知道的事：任务来源确实随 HTTP 落到记录里；diff 里 `wordCount` 的变化如实报出；回滚把正文逐字换了回去。
- **伏笔记录**：真实实例上把「建卡 → 记埋点 → 回收 → 检查页干净 → 检索按生命周期作答」跑通了一遍（`12` §2.2）。两件只有真跑才知道的事：回收之后检查页确实干净（`status` 与 `payoffIn` 同一次写入，M6 读的是同一份记录）；面板拿到的摘要与卡片文件一致（原句没在某一层被丢掉）。
- **我没能验证的两件事**，都只能由作者点（沙箱够不到）：
  1. **模型的那两轮**（M6 模型检查、M4 去 AI 味检查 / 润色）——隔离实例没有可用的模型路由，会话以 `reason: 'error'` 结束、日志里只有 header。
  2. **面板交互**：八份文档 §4 各有一张清单（`05` 17 项 / `06` 10 项 / `07` 12 项 / `08` 11 项 / `09` 8 项 / `10` 8 项 / `11` 15 项 / `12` 12 项）。**优先点这四件事**：检索页三种问法（`06`）→ 检查页确定性报告 + 忽略记忆（`07`）→ 模型检查一轮（`08`）→ 去 AI 味检查 + **定位到正文**（`09`）。加一件 M7 的：**先点出一张角色卡再点「修改记录」**（`11` §4.1b）。加一件伏笔的：**在正文里记一条、回收一条，再从「伏笔」页签点两个箭头跳回去**（`12` §2.3）。

### 两条会绊住下一次的环境事实

1. **host 半要换进程**：`pnpm run build` 之后浏览器半刷新即生效，**host 半（新路由/新行为）必须有一个新进程**——`patchReload: live` 只热重载 `cordis.patch.yml`，不替换插件模块（源码证据与判定方法见 `01` §4）。新路由报 404 时先看 `/api/novel/ping` 返回的 `routes`。
2. **隔离实例**：`DSH_HOME=.dsh-home`、`DSH_NOVEL_ROOT=.spike-novel`（已 gitignore），里面是我留的**故意写坏的测试书**（正文「御剑而起」vs 卡片「尚未筑基」），用来复现模型检查。启动命令见上文「开发」。另外我的沙箱里覆盖写已存在的文件会被 Windows DACL 拦（`06` §3.3），新建文件正常——**M7 这轮又踩了一次**：第一次跑修改记录的探针时两次写入其实全部 403，列表里只剩脚手架那一版，看起来像「M7 没记录」；把实例进程换成不受文件围栏约束的启动方式后才跑通 update 与回滚（`11` §4.2）。**在隔离实例上验任何「改写已有文件」的路径之前，先确认这一步没在被静默拦掉。** P5 另加一个 `.spike-novel-perf/`（同样已 gitignore）：`spike/perf-check.mjs` 每次运行重新生成的合成百万字工程，几 MB 生成文本，不是产品的一部分。

### 下一步（按优先级）

1. **P5 剩下的三块**：导出（EPUB / 投稿格式）、快捷键、错误处理。性能那块的**下一步不是继续优化插件**——暖扫描剩下的大头（400 章约 120 ms、1000 章约 300 ms）几乎全是 `dsh-fs-local` 列举时每个子项的 `realpath`，插件的能力面里没有更便宜的列举原语，目录令牌又不能用来跳过列举（`10` §3.4 有速率证据）。真要再快，得走 DSH 侧：轻量列举，或文件变更通知（需求 §6 提过 `workspaceFiles.changes`，**可用性未验证**）。**先量一次再动手。**
2. **小而完整**：M5 的模型问答（用检索出的片段回答开放问题）；把「润色 / 去 AI 味」接到**选中段落**（需要编辑器支持范围选择）。
3. **M7 的后续**（都在 `11` §5）：记录写入失败时面板不会说；面板外的改动不进记录（所以「最新一版」可能与磁盘不一致）；diff 没有左右对照视图；历史列表只取最近 50 条、没有翻页；`Ctrl+Z` 的绑定位置是一处需求偏差，全局快捷键策略与 P5 的「快捷键」一起定。
4. **伏笔的后续**（都在 `12` §4）：原句会过期而**没有对应的检查规则**（需要在 host 侧也有一份 `findQuote`，或把它挪成两边共用的纯模块）；没有「按章看伏笔」的视图；`plannedPayoff` 只能手改 YAML；`reinforcedIn` 也只能手改（加 `reinforcedQuote` 是自然的下一步）。

### 明确的欠账

物理删除（DSH 没有删除原语，插件不越沙箱）；未保存缓冲只在切章节时提示，切页签不提示；`beats` 只有 ↑/↓ 没有拖拽；模型层不支持「忽略某条」（`08` §2.4，理由与备选都在那里）；段落级润色未做（`09` §5）；模型的两轮与页面交互未验证（见上）；**暖扫描仍是 O(文件数)，瓶颈在 `dsh-fs-local` 的逐子项 `realpath`（1000 章约 300 ms），插件内无解**（`10` §5）；扫描缓存没有上限或淘汰，持仓随书增长（一本百万字的书约十几 MB）；**修改记录只记面板的写入**，在 VSCode 里直接改文件不会产生版本（`11` §5）；**伏笔的原句会过期**且没有「原句已失效」的检查规则（`12` §4）。
